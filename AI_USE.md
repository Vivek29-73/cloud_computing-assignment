## How I checked the AI output
- I ran every script myself and read the output. Nothing was assumed to work.
- Data: clean.py counts add up (3,000 = 1 + 1 + 9 + 48 + 49 + 2,892); re-running reproduces the same SHA-256.
- Model: validation scored with tools/score.py for the teacher, the untrained Pythia-70M and both students; model checksums match the tar files.
- Network: tools/nacl_sim.py gives 6/6 on the sample packets.
- Code: ruff and 5 unit tests (pytest) pass locally.
- Service: tested the endpoints, headers, fault injection (HTTP 500 with the exact body), 50 sequential requests under 1 CPU / 1 GiB.
- Kubernetes: rolling update, rollback, pod deletion, load balancing and cold start were observed and measured by me; the Locust load test was run with the standard command.
- Credentials: S3 keys are random strings generated at deploy time and kept in Kubernetes Secrets, not in Git.

## Things the AI got wrong or that failed first time
- Large pasted terminal blocks were garbled; I switched to downloaded files.
- Ollama on Windows was unreachable from WSL; I installed it inside Ubuntu.
- The newest k3s refused to start on cgroup v1; I enabled cgroup v2 in .wslconfig.
- The first teacher prompt produced extra text after the JSON; a stop sequence and token limit were added (settings beyond temperature 0 and seed 42).
- The teacher prompt was refined once after I saw 5 validation outputs. Validation data was never used for training.
- network/nacl.json was missing from the repo; my unit test caught it.
- My GitHub token lacked the workflow scope, so the first push of the workflow file was rejected.
